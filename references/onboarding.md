# 首次设置

## 严格顺序

不得把以下步骤合并，也不得反过来：

```text
1. 确认 campus 或 social
2. 请求简历文件
3. 原件归档并提取文本
4. 展示画像、优势、短板、岗位方向
5. 用户确认或纠正画像
6. 收集路线专属偏好
7. 创建并激活 Campaign
```

如果用户已经在第一条消息中附带简历，直接使用它，不要重复索要。

## 路径识别

- “应届、XX届、秋招、春招、校园招聘、校招” → `campus`。
- “跳槽、工作几年、社招、正式工作、换工作” → `social`。
- 同时出现两类词，或只有“求职/找工作” → 询问用户选择。
- 一个 Profile 可以保存多个 Campaign，但第一次只建立一个。

## 简历导入命令

```bash
python3 scripts/jobctl.py resume import \
  --file <用户文件> --kind base --set-base --honesty-checked \
  --json
```

支持 PDF、DOCX、PNG、JPG、MD、TXT。提取失败时停止，不问后续偏好，只请用户换成可读取格式。

## 画像输出要求

必须先把分析展示给用户，再建 Campaign。内容只能来自简历：

1. 画像速览：学历/工作年限、专业或业务域、技能、经历主线。
2. 优势 3 条：格式为“结论 —— 简历证据”。
3. 短板 2–3 条：格式为“缺口 —— 会卡在哪个环节”。
4. 推荐 2–3 个真实岗位方向；第一个标记为主推。
5. 每个方向写 2–4 个典型招聘标题、推荐理由和需要补的内容。

没有证据就写“简历未提供，需要用户确认”，禁止猜测。

## 采集问题

通用问题：目标方向、城市/远程、行业、意向公司、排除公司、每天想看几个岗位。

校招问题：毕业届别、招聘季、正式岗/实习、学历专业限制。

社招问题：工作年限、目标职级、转行业意愿、到岗周期、城市/远程。

每日数量只能是 1–20；默认 5。数量是上限，不保证凑满。

## 隐私

可经用户确认后保存姓名、电话、邮箱、教育和工作经历，用于重复网申。不得保存密码、Cookie、验证码、
短信内容、身份证号、银行卡号、电子签名或健康/犯罪/征信答案。所有注入外部检索任务的画像必须脱敏，
不能含姓名、电话、邮箱、地址或照片。
