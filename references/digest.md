# 日报

## 顺序

1. 超过 24 小时未处理的推荐。
2. 到期的投递状态检查、笔试、面试和其他 next action。
3. 今日新的正式推荐。
4. 待核实的 C 级岗位。
5. 来源和降级说明。

## 24 小时判定

推荐状态为 `pending`、`preparing` 或 `snoozed`，`decision_due_at <= now`，岗位仍 active，且没有正式 application，
才进入待决策区。生成定制简历、开始填表、保存草稿、正式投递或选择“保留明天”都算进展并重置时钟。

每条给两个操作：归档，或保留到下一次日报。用户不回答不自动归档。

## 投递待跟进卡

正式提交后若没有显式待办时间，`next_action_at` 默认为投递日期后第 3 个自然日的 Campaign 日报时间。
到期卡片包含公司、岗位、投递日期、当前阶段、距上次更新天数、申请入口和三个操作：

- 已查看，暂无更新：调用 `application check-status --result no-update`，从检查日顺延 3 个自然日。
- 状态已更新：确认新阶段；笔试或面试时间已知时同时保存为 `next_action_at`。
- 停止状态提醒：清空 `next_action_at`，不删除投递。

用户忽略时不修改数据，下一份日报继续显示。终止态投递不再进入提醒区。

## 岗位卡

包含公司、岗位、城市、来源等级、官方核实时间、匹配分、置信度、最强证据、最大缺口、建议修改点、截止日期、
官方投递链接、岗位 ID，以及“定制简历/填写网申/归档”入口。
