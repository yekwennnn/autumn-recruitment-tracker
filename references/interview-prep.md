# 面试排练

投递追踪能告诉你"XX 让你去一面了"，但从那一刻到面试当天，工具原本什么都帮不上。
这一节补上：**备题 → 模拟 → 复盘**。

三件事共用一个前提——**面试官手里拿的是你投这家时用的那一版简历**，不是你最新那版。
备题和模拟都必须基于那一版，不然练的是另一场面试。

数据存 `state/interview_bank.json`（`state/*.json` 已被 gitignore）。
**无人值守绝不进入本流程**，全程需要人在场。

## 触发

「帮我准备 XX 的面试」「陪我模拟一下面试」「明天二面了」「面完了，复盘一下」。

投递追踪那边记到 `笔试/一面/二面/三面/HR面` 时，顺口提一句"要不要排练一下"——
但**排练本身不改任何投递状态**，面试结果仍然由用户说了才 `apply.py stage`。

## 模式一：备题

### 取材（四样，缺一不可）

1. **投这家时用的简历版本**——
   ```bash
   python3 $SKILL_DIR/scripts/apply.py list --applications $SKILL_DIR/state/applications.json --json
   ```
   按公司名找到那条记录的 `resume_version`，读 `resumes/versions/<那个版本>/resume.txt`。
   **不要用 active 版**——面试官看的是当时投出去的那一份。
   记录里没写 `resume_version`（省了 `--resume-version`）→ 直接问用户投的是哪一版，别猜。
2. **JD**——`state/seen_postings.json` 里该岗位的 `match.jd_summary`，或用户贴的原文。
3. **素材库**——`resumes/experience-bank.json`，答题的弹药都在这儿。
4. **公司信息**——需要时联网查（走 web-access）：主营业务、近期动态、这个岗位在公司里做什么。

### 出题三路

| 路 | 打什么 | 出题依据 |
|---|---|---|
| **行为题** | 简历上的薄弱点和可深挖处 | 那一版简历里每段经历都可能被追问"具体你做了什么"；`match.gaps` 指出的差距一定会被问 |
| **动机题** | 为什么是这家、这个岗位、这个城市 | JD + 公司业务；校招的动机题权重比社招高得多 |
| **专业题** | JD 的硬技能项 | JD 写明要求的每一项，都要有一道题 |

**必出的两类题**（校招几乎每场都有，别漏）：

- **简历硬伤题**——那一版简历里最容易被质疑的地方。空窗期、跨专业、实习短、
  成绩排名、"为什么本科不是这个方向"。这类题最难临场答好，必须提前想。
- **反问环节**——「你有什么想问我的」。准备 2-3 个，问出你真的想知道的事
  （团队构成、这个岗位一年后大概在做什么、考核看什么），别问工资福利，也别不问。

可选：联网搜该公司近期面经（牛客、应届生论坛）。搜到的题**标注来源和日期**，
面经真假掺半，标了用户才知道该信几分。

### 输出

题单按三路分组，每题给：题目 + 考察点 + **从素材库取哪段经历来答**（写清 `id`）。
**不要直接给标准答案全文**——那会变成背稿，面试官一眼看得出来。给要点和素材指向就够，
用户自己组织语言才是练。

存进 `interview_bank.json`。

## 模式二：模拟

Claude 演面试官，一问一答，**一次一题，不要一口气抛五道**。

每题用户答完，反馈三件事（简短，不要写成小作文）：

1. **STAR 完整度**——缺哪一块？最常见的是只讲 A（做了什么）不讲 R（结果怎样），
   以及 S/T 交代不清导致面试官不知道这事难在哪。
2. **红旗话术**——踩到就直说：
   - 贬低前雇主／同事／学校
   - 数字前后矛盾（这是最致命的，面试官会顺着追问）
   - 明显的背稿感（书面语、排比句、"首先其次最后"）
   - 把团队成果说成个人成果（追问一句就露）
   - 答非所问、绕圈子
3. **更优表达**——同样的事实换个说法会好在哪。**只改表达，不改事实。**

**追问加压模式**（用户要求时开）：对同一件事连问三层 why，模拟真实面试官的深挖。
这是检验素材真伪最有效的方式——编的东西撑不过第二层。

答得好的回答，问用户要不要沉淀：STAR 故事存进 `experience-bank.json` 的 `star_stories`，
通用问答（职业规划、优缺点）存进 `webapply-profile.json` 的 `custom_answers`。
**面试练出来的答案，网申开放题直接能用。**

## 模式三：复盘

真实面试之后做，这是整个流程里最值钱的一步——**真题比任何预测题都准**。

1. 问用户被问到了什么（记不全就记住的那几道）。
2. 每道题记进 `interview_bank.json`，标 `source: "real"`。
3. 问哪几道答得不好、当时卡在哪，记进 `lessons`。
4. 同公司/同方向下次备题时，**真题优先出，预测题往后排**。

复盘不评判用户表现，只收集信息。面试完人是累的，别追着复盘，
用户说"改天再说"就存个占位下次再问。

## 数据结构

```json
{
  "schema_version": 1,
  "updated_at": "…",
  "companies": [
    {
      "company": "…",
      "title": "…",
      "application_id": "对应 applications.json 里的 id，可为 null",
      "resume_version": "面试官手里那一版",
      "rounds": [
        { "stage": "一面", "date": "YYYY-MM-DD",
          "questions": [
            { "q": "题目",
              "type": "行为|动机|专业|硬伤|反问",
              "source": "predicted|real|面经",
              "source_note": "面经来源与日期",
              "material_ids": ["acme-intern"],
              "rehearsed": true,
              "feedback": "模拟时的要点反馈摘要" }
          ],
          "lessons": ["答不上来的地方、当场的教训"] }
      ]
    }
  ]
}
```

**不存逐字稿。** 只存题目、要点、反馈摘要——完整对话既没必要留，也是隐私负担。

## 红线

- **不替用户编经历**。面试答案的事实来源只有两个：素材库（用户确认过的）和用户当场说的。
  模拟时用户临时编了一段，要提醒他："这段素材库里没有，真面试被追问细节能撑住吗？"
- **不做语音**，纯文字。
- **不承诺结果**。别说"这样答肯定过"，练的是表达和准备度，不是保证。
- 排练**不改投递状态**。
