# 求职助手 v3.0

中文名是「求职助手」；`job-copilot` 是安装和调用时使用的技术标识。

一个陪你走完整个求职流程的 Agent Skill：分析简历、确定方向、找岗位、对照 JD 打分、定制简历、填写网申草稿、记录进展、提醒查状态，还能陪你模拟面试。

你不需要会编程，也不需要看懂数据库或命令行。照着本页把示例句子发给 Agent，就能开始使用。

> 最重要的安全规则：求职助手可以帮你填写网申，但永远不会点击“最终提交”。提交前必须由你本人检查并操作。

## 你可以用它做什么

- 先区分校招和社招，再分析你的简历。
- 根据学历、经历、技能和偏好，建议 2～3 个求职方向。
- 优先从公司官网和官方招聘渠道找岗位。
- 把岗位 JD 和你的简历放在一起评分，并解释匹配证据和差距。
- 针对某个岗位改简历，保留每个历史版本。
- 使用你本人提供的证件照生成定制 PDF 简历。
- 在真实招聘网站中填写信息、上传简历，并停在提交前。
- 区分“网申草稿已填”和“已经正式投递”。
- 记录笔试、面试、Offer 等进度，提醒你查看投递状态。
- 针对真实岗位进行逐题模拟面试和回答训练。

## 开始前准备 3 样东西

1. 一份你当前使用的简历，优先使用 PDF 或 DOCX。
2. 一张你本人的证件照。如果暂时没有，也可以先完成分析和文字修改，生成最终带照片 PDF 时再提供。
3. 一个能使用 Skill 的 Codex Agent。推荐使用 Codex 桌面应用，这样上传文件和操作浏览器更方便。

## 第一步：安装求职助手

在 Codex 中新建一个任务，把下面这句话完整复制给 Agent：

```text
请从 GitHub 仓库 https://github.com/yekwennnn/job-copilot 安装 job-copilot Skill。安装完成后告诉我，并且不要修改仓库里的文件。
```

Agent 完成安装后，建议新建一个任务再开始求职流程。这样它能稳定识别刚安装的 Skill。

如果 Agent 没有识别安装请求，再发送：

```text
请使用 skill-installer，从 GitHub 仓库 yekwennnn/job-copilot 安装名为 job-copilot 的 Skill。
```

安装成功后，你在新任务中输入 `$job-copilot`，Agent 应该能够识别它。

## 第二步：第一次设置

新建一个任务，复制下面这句话：

```text
使用 $job-copilot 开始我的求职流程。请先问我是校招还是社招，再让我上传简历。
```

Agent 会先问你走哪条路径。直接回答：

```text
校招
```

或者：

```text
社招
```

选好路径后，Agent 才会请你上传简历。点击输入框附近的附件按钮，选择你的简历文件，然后发送：

```text
这是我目前的基础简历，请存档、解析并分析。没有写在简历里的事实不要猜。
```

求职助手会给你这些结果：

1. 画像速览，包括学历、专业、毕业时间或工作年限、核心技能和经历主线。
2. 三项有简历证据的优势。
3. 两到三项短板，以及它们会影响哪个招聘环节。
4. 两到三个推荐方向，并明确一个主推方向。
5. 需要你确认或补充的信息。

认真看一遍分析。如果事实准确，回复：

```text
画像确认无误，继续问我求职偏好。
```

如果有错误，直接指出原文和正确说法，例如：

```text
有一处需要更正：我不是独立负责整个项目，而是负责需求分析和上线验收。请按这个事实更新画像。
```

## 第三步：告诉它你想找什么

### 如果你走校招

可以照着下面的模板改完后发送：

```text
我的校招偏好如下：
1. 毕业年份：2027 届
2. 招聘季：2026 秋招
3. 岗位类型：正式校招，也接受实习
4. 目标方向：数据产品、商业分析
5. 城市：深圳、广州，也接受上海
6. 意向公司：暂无
7. 每天最多推荐：5 个
```

### 如果你走社招

可以照着下面的模板改完后发送：

```text
我的社招偏好如下：
1. 工作年限：2 年
2. 目标职级：产品经理
3. 目标方向：企业数据产品、BI、B 端 SaaS
4. 是否接受转行业：接受
5. 到岗时间：随时
6. 城市或远程：深圳、广州，不接受长期异地办公
7. 意向行业：互联网、企业服务、零售、电商、金融
8. 意向公司：暂无
9. 每天最多推荐：3 个
```

每天推荐数量可以选 1、3、5、10，或自己填写 1～20。这个数字是上限，不是必须凑满的数量。只有 3 个合格岗位时，即使你设置了 5 个，日报也只会给 3 个。

确认信息后发送：

```text
请保存这些偏好，建立求职 Campaign，并告诉我设置结果。
```

Campaign 可以理解为一条独立的求职路线。例如“广州社招产品经理”和“上海校招数据分析”可以分别建立，不会混在一起。

## 第四步：生成今天的岗位日报

发送：

```text
运行今天的岗位日报。优先公司官网和官方招聘渠道；聚合平台只能放进待核实区，不要用低置信度岗位凑数。
```

一条正式推荐通常会包含：

- 公司、岗位和城市。
- 官网或官方招聘来源。
- 官方核实时间和投递链接。
- 匹配分与置信度。
- 最强匹配证据和最大缺口。
- 建议修改的简历内容。
- 截止日期；页面没写时会显示未注明，不会猜日期。

来源为 A 或 B、满足硬门槛、达到你的最低匹配分并且证据覆盖充分的岗位，才会进入正式推荐。聚合平台发现但还没回到官方渠道核实的 C 级岗位，只会出现在“待核实”区，不占每日名额。

## 第五步：查看一个岗位是否适合你

如果岗位已经在日报中，发送：

```text
详细分析今天第一个岗位和我的匹配度。
```

如果你在其他地方看到一个 JD，可以粘贴文字或上传截图，然后发送：

```text
请使用 $job-copilot 对照我的基础简历分析这个 JD。先检查硬门槛，再评分，并分别告诉我简历表达缺口、真实能力缺口和下一步行动。
```

评分不会把“接触过”当成“熟练”，也不会把“使用 AI 辅助完成”当成你独立具备全部开发能力。

## 第六步：针对岗位修改简历

先明确选择岗位，再发送：

```text
根据今天第一个岗位修改我的简历。只使用简历、我已经确认的事实和我接下来明确补充的信息；先问我关键经历，不要直接编写不存在的项目或数字。
```

Agent 会把差距分为三类：

- 表达缺口：经历真实存在，只是原简历没写清楚。
- 信息缺口：简历没写，需要问你是否真实做过。
- 能力缺口：你确认没有这项能力，只能制定学习计划，不能写进简历。

回答问题时尽量提供真实细节，例如你做了什么、和谁协作、结果如何。如果没有准确数字，直接说没有，不要为了好看临时编一个。

文字确认完成后，上传你本人的证件照并发送：

```text
这是我本人的证件照。请使用对应的校招或社招模板生成最终 PDF，检查照片、页数、占位符和文件可打开性，然后注册为新的定制简历版本。
```

求职助手不会生成、换脸、重绘或猜测你的真人证件照。没有照片时，它可以先完成文字稿，但应暂停最终 PDF 交付。

## 第七步：填写网申，但由你提交

先在 Chrome 中打开目标岗位的正式申请页面，并确保你已经登录。然后发送：

```text
请使用 $job-copilot 填写这个岗位的网申。使用刚生成的定制简历，只填写已经确认的信息，上传后检查文件名，并停在最终提交前让我检查。
```

Agent 会先确认：

1. 这是该岗位的正式申请地址。
2. 使用哪一版简历。
3. 姓名、联系方式、教育和经历等申请资料是否完整。
4. 浏览器连接是否可用。

你可能需要对期望薪资、调岗、出差、加班、转行业、内推人、开放题和到岗日期进行单独确认。

以下内容永远不会由求职助手自动填写或确认：

- 密码、Cookie、短信验证码和图形验证码。
- 身份证号和银行卡信息。
- 健康、残疾、犯罪或征信信息。
- 背景调查授权、电子签名和法律声明。
- 最终真实性承诺框。
- 最终提交按钮。

遇到验证码、未知必填字段或敏感声明时，Agent 会暂停并让你接管。填完后它只记录“草稿已填”或“等待检查”，不会假装已经投递。

你检查页面并亲自提交成功后，发送：

```text
我已经正式提交了这个岗位的网申，请记录投递并设置默认的状态检查提醒。
```

只有你明确说已经提交，或浏览器明确观察到申请成功页或申请编号时，系统才会把它标为“已投递”。

## 第八步：查看投递状态和提醒

正式投递后，如果你没有指定日期，求职助手默认在投递后的第 3 个自然日、日报时间提醒你查看状态。

生成日报时发送：

```text
生成今天的求职日报，并列出需要查看状态的投递。
```

检查完官网后，可以这样回复：

```text
我已经查看了这个岗位，暂无更新，请三天后再提醒我。
```

或者：

```text
这个岗位状态更新为一面，请记录，并问我面试时间。
```

如果以后不想再收到某个岗位的状态提醒：

```text
停止这个岗位的状态提醒，但不要删除投递记录。
```

提醒会出现在下一份日报中，不等于手机系统推送。你需要主动运行日报；如果你的 Agent 支持定时任务，也可以另外请它每天定时生成日报。

## 第九步：模拟面试

当你收到真实面试通知时，直接告诉 Agent：

```text
这家公司通知我一面了，请记录真实进展，然后问我要不要进行模拟面试。
```

如果同一家公司有多个岗位，求职助手会列出候选让你选，不会随便更新第一条。

确认开始后发送：

```text
开始一轮 6 题的文字模拟面试，一次只问一题。我每答完一题，你立刻评分、指出问题、给出不虚构事实的润色示例，再问我是重答还是继续。
```

六题通常覆盖：

1. 自我介绍和求职动机。
2. 简历经历深挖。
3. JD 核心能力验证。
4. 协作、冲突或失败经历。
5. 岗位场景题或业务案例题。
6. 反问面试官和收尾表达。

每题按相关性、事实证据、表达结构、岗位契合度、简洁清晰度评分。润色只使用你真实提供过的信息；缺少数字时会提示补充，不会擅自制造业绩。

六题结束后，你会得到综合得分、优势、优先改进项、高频追问题、推荐反问和一页式面试前复习要点。

## 一次完整使用示例

第一次使用时，你可以按这个顺序和 Agent 对话：

```text
你：使用 $job-copilot 开始我的求职流程。请先问我是校招还是社招，再让我上传简历。

Agent：你准备走校招还是社招？

你：社招。

Agent：请上传当前简历。

你：这是我的基础简历，请存档、解析并分析。没有写在简历里的事实不要猜。

Agent：这里是画像、优势、短板和三个建议方向……

你：画像确认无误。我工作 2 年，想做 B 端 SaaS 产品，接受转行业，城市是深圳和广州，每天最多推荐 3 个。

你：运行今天的岗位日报。

你：根据第一个岗位修改简历，只使用已确认事实。

你：请填写这个岗位的网申，停在最终提交前。

你：我检查并正式提交了，请记录投递。

三天后你：生成今天的求职日报，并列出需要查看状态的投递。

收到面试后你：这个岗位通知我一面了，请记录并开始模拟面试。
```

## 数据和隐私

- 求职资料默认保存在你自己的本地 `data` 目录中，不会把简历和照片塞进数据库正文。
- 数据库只记录文件路径、哈希、版本关系、岗位和投递状态。
- 密码、Cookie、验证码、身份证号、银行卡号、电子签名等敏感信息不应进入数据库或日志。
- 模拟面试不会保存你的逐字回答，也不会保存完整的润色答案，只保存题目标签、分数和简短改进摘要。
- 删除岗位默认是软归档，历史记录仍可追溯。
- 不要手动修改数据库。如果需要导出、备份或更正记录，直接告诉 Agent 你的目标。

## 常见问题

### Agent 说找不到 `$job-copilot`

先确认安装任务已经完成，然后新建一个 Codex 任务再试。如果仍然找不到，发送：

```text
请检查 job-copilot Skill 是否已经安装并可被当前任务发现；如果没有，请从 yekwennnn/job-copilot 重新安装。
```

### 简历解析失败

优先把简历另存为 PDF 或 DOCX 后重新上传。如果是扫描件，确保页面清晰、方向正确。仍然失败时，可以导出为纯文本 TXT 再上传。解析失败时求职助手应停止分析，不会猜测你的经历。

### 没有生成足够多的岗位

这是正常的。每日数量是上限，系统不会为了凑数把过期、低匹配或未核实的岗位塞进正式推荐。你可以明确说“放宽方向”“放宽城市”或“允许聚合平台进入待核实区”，但 C 级来源仍不会占正式配额。

### 没有证件照

可以先完成简历文字修改。最终交付带照片 PDF 前，请上传你本人的照片。如果旧 PDF 中有照片，也可以请 Agent 尝试提取，并要求它说明照片来自哪个文件。

### 浏览器没有继续填写

保持 Chrome 中的申请页面打开，然后发送：

```text
申请表已经在 Chrome 中打开。请检查浏览器连接和当前页面，告诉我需要完成哪一步，然后继续填写并停在提交前。
```

如果网站出现验证码、短信确认或未知敏感字段，你需要亲自接管，这是正常的安全暂停。

### 为什么三天后没有弹出系统通知

求职助手的默认提醒会进入下一份求职日报，不是手机或电脑的系统推送。主动发送“生成今天的求职日报”即可查看。如果你使用的 Agent 支持定时任务，可以单独让它每天固定时间运行日报。

### 如何更新到新版本

发送：

```text
请把已安装的 job-copilot 更新到 GitHub 仓库 yekwennnn/job-copilot 的最新版本。保留我的 data 目录和全部个人求职记录，更新前先备份。
```

## 使用边界

求职助手是求职辅助工具，不会代替你保证经历真实性、判断劳动合同、作出职业选择或完成最终法律承诺。提交网申、签署声明、接受 Offer 前，请你本人再次检查。
